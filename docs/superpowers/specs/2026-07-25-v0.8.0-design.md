# KiloCode Desktop v0.8.0 设计文档

> 日期：2026-07-25 | 版本：v0.8.0 | 状态：待审核

---

## 一、概述

v0.8.0 是 KiloCode Desktop 的第一个增量版本，聚焦三个高优先级功能：

1. **Session Fork UI** — 会话分叉的用户界面入口
2. **Auto-Recovery Completion** — 自动恢复完善（resumeSession 接入 + Toast 通知）
3. **Electron Desktop Runtime Verification** — 桌面运行时验证与修复

目标：补全核心功能缺失，确保桌面端可正常运行。

## 二、Session Fork UI

### 2.1 需求

用户可从任意消息点分叉对话，创建新会话继续探索不同方向。API 方法 `kiloClient.forkSession` 和 sessionStore action 已存在，仅缺 UI 入口。

### 2.2 方案选择

| 方案 | 描述 | 结论 |
|------|------|------|
| A. 消息 hover 浮出按钮 | hover 时右上角显示 GitBranch 图标 | ✅ 采用 |
| B. 右键菜单分叉 | 右键消息弹出上下文菜单 | ❌ 不够直观 |
| C. 消息底部常驻操作栏 | 每条消息底部常驻操作按钮 | ❌ 视觉噪音大 |

选择方案 A 的理由：最符合 Codex 简洁风格，交互自然，实现轻量。

### 2.3 交互设计

1. `AssistantMessage` 和 `UserMessage` 外层包裹 `group` 容器（Tailwind group hover 机制）
2. hover 时在消息右上角浮出 `GitBranch` 图标按钮：
   - 默认：`opacity-0 group-hover:opacity-100` 过渡
   - 颜色：`text-[var(--text-tertiary)]` → hover `text-[var(--brand-primary)]`
   - 尺寸：14px 图标 + 24px 触摸区域
3. 点击按钮调用 `sessionStore.forkSession(activeSessionId, message.id)`
4. 分叉成功后自动切换到新会话
5. `/fork` 斜杠命令：从最后一条消息分叉当前会话
6. 未连接 CLI 时：本地模拟分叉（复制消息到新会话）

### 2.4 数据流

```
hover 消息 → 显示 GitBranch 按钮 → 点击
  → sessionStore.forkSession(sessionId, messageId)
    → [已连接] kiloApi.forkSession(id, fromMessageId)
      → 成功：新会话加入列表 → 切换到新会话 → 加载消息
      → 失败：Toast 提示「分叉失败」
    → [未连接] 本地模拟分叉
      → 复制消息到新会话 → 切换到新会话
```

### 2.7 本地模拟分叉逻辑

未连接 CLI 时，`forkSession` 降级为本地操作：

```typescript
// sessionStore.ts forkSession 降级逻辑
forkSession: async (id: string, fromMessageId?: string) => {
  const connected = useConnectionStore.getState().connected
  if (connected) {
    // 真实 API 调用（已有逻辑）
    const newSession = await kiloApi.forkSession(id, fromMessageId)
    // ...
  } else {
    // 本地模拟分叉
    const state = get()
    const sourceSession = state.sessions.find(s => s.id === id)
    if (!sourceSession) return

    // 复制消息到分叉点
    const forkIndex = fromMessageId
      ? state.messages.findIndex(m => m.id === fromMessageId)
      : state.messages.length
    const forkMessages = forkIndex >= 0
      ? state.messages.slice(0, forkIndex + 1)
      : [...state.messages]

    const newSession: KiloSession = {
      id: `local-fork-${Date.now()}`,
      title: `${sourceSession.title} (分叉)`,
      mode: sourceSession.mode,
      model: sourceSession.model,
      status: 'active',
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString(),
      workingDir: sourceSession.workingDir,
      messageCount: forkMessages.length,
    }

    set(s => ({
      sessions: [newSession, ...s.sessions],
      activeSessionId: newSession.id,
      messages: forkMessages.map(m => ({ ...m, sessionId: newSession.id })),
    }))
  }
}
```

## 三、Auto-Recovery Completion

### 3.1 需求

persist + 崩溃重载已完成，但 `resumeSession` 未接入，缺少恢复提示。

### 3.2 方案选择

| 方案 | 描述 | 结论 |
|------|------|------|
| A. 连接恢复 + Toast 提示 | resume + Toast 通知 | ✅ 采用 |
| B. 静默恢复 | 自动 resume，无提示 | ❌ 用户无感知 |
| C. 弹窗确认 | 恢复前弹窗询问 | ❌ 过于打扰 |

选择方案 A：平衡信息透明度和用户体验。

### 3.3 设计

#### 3.3.1 resumeSession 接入

在 `useKiloConnection` 首次连接成功后：

1. 检查 `sessionStore.activeSessionId` 是否存在
2. 若存在，调用 `kiloApi.resumeSession(id)` 恢复服务端会话状态
3. 成功后显示 Toast「会话已恢复」
4. 失败时静默处理（本地 persist 数据仍可用）

#### 3.3.2 Toast 通知组件

新增轻量级 Toast 通知系统：

- **Toast 组件**：固定在窗口右上角，自动消失（3 秒）
- **toastStore**：管理 Toast 队列（Zustand store，最多同时显示 3 条）
- **Toast 类型**：`info`（Cyan 图标）、`success`（绿色图标）、`warning`（橙色图标）、`error`（红色图标）

Toast 组件设计：
```
┌─────────────────────────────┐
│ ℹ  上次会话已恢复            × │
└─────────────────────────────┘
```
- 背景：`var(--bg-secondary)` + 边框 `var(--border)`
- 图标颜色按类型区分
- 右侧关闭按钮
- 自动消失动画（fade out）

#### 3.3.3 中断恢复提示

persist 恢复后检测中断状态：

1. `sessionStore` 新增 `wasInterrupted: boolean` 字段
2. persist `merge` 函数中：若恢复的 `isStreaming` 为 true，设置 `wasInterrupted = true`（同时重置 `isStreaming = false`）
3. App 组件 mount 时检查 `wasInterrupted`，若为 true 则显示 Toast「上次会话中断，已恢复到最近状态」并重置标记

### 3.4 数据流

```
App 启动
  → persist 恢复 sessionStore
    → merge 检测 isStreaming=true → wasInterrupted=true, isStreaming=false
  → App mount 检查 wasInterrupted
    → [true] Toast「上次会话中断」→ 重置 wasInterrupted=false
  → useKiloConnection 连接成功
    → 检查 activeSessionId
      → [有] kiloApi.resumeSession(id)
        → 成功：Toast「会话已恢复」
        → 失败：静默（本地数据可用）
      → [无] 无操作
```

### 3.5 涉及文件

| 文件 | 变更 |
|------|------|
| `src/hooks/useKiloConnection.ts` | 连接成功后调用 resumeSession |
| `src/stores/sessionStore.ts` | 新增 `wasInterrupted` 字段 + merge 逻辑 |
| `src/stores/toastStore.ts` | **新增** Toast 状态管理 |
| `src/components/common/Toast.tsx` | **新增** Toast 通知组件 |
| `src/App.tsx` | 挂载 Toast 容器 + 检查 wasInterrupted |

### 3.6 toastStore 接口

```typescript
interface ToastItem {
  id: string
  type: 'info' | 'success' | 'warning' | 'error'
  message: string
  duration?: number  // 默认 3000ms
}

interface ToastState {
  toasts: ToastItem[]
  addToast: (toast: Omit<ToastItem, 'id'>) => void
  removeToast: (id: string) => void
}
```

## 四、Electron Desktop Runtime Verification

### 4.1 需求

构建通过但从未实际启动验证，需确认桌面端可正常运行。

### 4.2 验证清单

| # | 检查项 | 预期 | 验证方式 |
|---|--------|------|----------|
| 1 | `npm run electron:dev` 启动 | 窗口正常显示 | 实际运行 |
| 2 | 自定义标题栏 | 最小化/最大化/关闭按钮可用 | 视觉检查 + 点击 |
| 3 | 系统托盘 | 图标显示，右键菜单可用 | 视觉检查 |
| 4 | CLI 子进程 | 自动启动或优雅降级到模拟模式 | 检查控制台日志 |
| 5 | 主题切换 | 深色/浅色/跟随系统正常 | 切换验证 |
| 6 | 窗口大小/位置 | 默认 1400×900，可调整 | 视觉检查 |
| 7 | 快捷键 | 全局/应用快捷键响应 | 按键测试 |

### 4.3 策略

1. 先运行 `npm run electron:dev` 启动应用
2. 按清单逐项验证
3. 发现问题则修复
4. 记录验证结果到 PROGRESS.md

### 4.4 可能的问题与预案

| 可能问题 | 预案 |
|----------|------|
| Vite dev server 端口不匹配 | 检查 vite.config.ts 和 electron main.ts 的 URL 配置 |
| preload 脚本路径错误 | 检查构建输出路径和 main.ts 中的 preload 路径 |
| 标题栏 overlay 不显示 | 检查 frame:false + titleBarStyle 配置 |
| 托盘图标缺失 | 检查 tray.ts 中的图标路径 |
| CLI 启动失败 | 确认优雅降级到模拟模式 |
